## What was built

The first real deliverable: [vision.md](../deliverables/vision.md) rendered to
`out/Vision.docx` with the 0.2 pipeline. Sections: problem, target users, six product principles
(P1–P6), scope (S1–S7) and **non-goals** (N1–N6), success metrics, solo operating model, risk

## The mental shift

A charter for a solo project is mostly a list of **refusals**. Every non-goal removes a whole
class of future work (moderation, billing, tenancy, legal exposure) that a single operator could
not sustain. Writing the metrics against concrete columns also forced a check that the data model
in PLAN §5 can actually produce them — which is the first time the docs constrained the schema
rather than the other way round.

## Gotchas hit

- The first title-page render only shows `title/subtitle/author/date`; `status` had to be
  repeated visibly in the Document control section (same finding as 0.2, now applied).
- Pandoc `--number-sections` numbers "Document control" as §1, so Executive summary is §2.
  Acceptable; an unnumbered front section would need `{-}` on the heading — noted for the SRS.
