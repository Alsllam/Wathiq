# 5.6 — Feedback, RAG evals and the docs loop

> **Phase:** 5 · **App:** backend + docs · **Commit:** `step(5.6): add reader feedback, RAG eval set with must-refuse scoring, close the Phase 5 docs loop` · **Date:** 2026-09-07

## What was built

The accountability layer around the RAG feature. **`GuideFeedback`**: any reader — anonymous
included — flags a published version as outdated/wrong/helpful; the admin lists open flags
(with guide slugs for context) and resolves them idempotently; a draft version id is rejected
as a forged request. **RAG evals**: a 10-case bilingual set of grounded Q&A pairs where **4 are
must-refuse** — off-topic questions and guides that don't exist yet — scored by a gated runner
that chunks and embeds the *real seeded guide* with the production chunker + bge-m3, retrieves
with the production math, answers through the real `GuideAnswerer`, and replicates the
service's citation policy; metrics are answer rate, refusal accuracy and clean-citation rate.
**Docs loop**: FR-GDE-001…004 flip to *Implemented* in the SRS, ai-safety.md 0.2 gains §8 — the
eight-link grounding chain and the RAG eval method — and database.md/api.md pick up the
feedback table and endpoints. All four docx re-rendered.

## The mental shift

Writing the eval set and the feedback feature in one step exposed that they are the **same
mechanism at two timescales**. The eval set is frozen feedback: each case says "for this
question, the correct behavior is this answer (or this silence)" — judged in seconds, by a
runner. Reader feedback is a live eval: each flag says "for this content, the world disagrees" —
judged in weeks, by humans. Both exist because the middle layer (the model) cannot know when
it's wrong; the design surrounds it with judges on both ends. That frame also settled a scoring
debate: refusal accuracy is not a penalty on helpfulness but the *other half of correctness* —
6 answer cases measure recall of what the corpus knows, 4 refuse cases measure precision about
what it doesn't, and only together do they describe a trustworthy assistant.

## Gotchas hit

- **`cd` into a path that assumed the old working directory** → `MSB1009: Project file does not
  exist`. The stale-binary scars paid off: recognized instantly (this exact error once ran
  yesterday's DLLs in 3.x), fixed with absolute paths, zero minutes lost. Ritual upgrade:
  compound commands start with `cd /home/user/Wathiq/backend`.
- **Section numbering in a hand-edited doc**: the RAG section first landed as §9 *above* §8 -
  pandoc's `--number-sections` would have silently renumbered the headings while the in-text
  cross-references ("§8 Planned hardening") kept the literal numbers. Caught by re-grepping
  `^# [0-9]` after the patch; the SRS cross-reference was fixed in the same pass.
- **The eval JSON travels between test projects**: `rag-cases.json` is a `CopyToOutputDirectory`
  item in Application.Tests, but the concrete runner executes in EFCore.Tests - MSBuild copies
  referenced projects' content transitively, so the structural test passed from the other
  project's output. Worth knowing WHY it works, not just that it does.

## Check yourself

1. Why does the eval runner *replicate* the ChatAppService citation policy instead of calling
   `IChatAppService` directly?
2. Feedback creation is anonymous but feedback on a draft version is rejected. What attack does
   that second rule close, given the first?

<details><summary>Answers</summary>

1. In the test graph the seams are faked (IGuideAnswerer, IEmbeddingGenerator) so the service
   path would eval the FAKES. The runner rebuilds the pipeline from the real parts (production
   chunker, live models, real keyed client) and mirrors the validation policy - accepting a
   small duplication so the score measures the shipping behavior. When 5.7's portal exists, a
   dev-box run through the HTTP endpoint becomes the end-to-end complement.
2. Anonymous create means anyone can write rows with any Guid they can guess. Requiring the
   version to be PUBLISHED means feedback can only attach to content a reader could actually
   have seen - a forged draft id (enumerating, or leaked from authoring) bounces with
   VersionNotPublished instead of letting outsiders probe which draft ids exist.

</details>
