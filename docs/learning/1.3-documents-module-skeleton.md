## The mental shift

"One DbContext per module" costs exactly four things and I now know each: a `ConnectionStringName`
(falls back to `Default`), a default schema, a **separate migrations history table** (otherwise
both contexts fight over `dbo.__EFMigrationsHistory`), and a second `IWathiqDbSchemaMigrator` so
the migrator applies both. Once those are paid, the compiler enforces the boundary: the test
`FindEntityType(typeof(IdentityUser)).ShouldBeNull()` is the ADR written as an assertion.

## Gotchas hit

- **Conventional registration is name-based.** `EntityFrameworkCoreDocumentsDbSchemaMigrator :
  IWathiqDbSchemaMigrator, ITransientDependency` was registered only as itself: ABP exposes an
  interface automatically only when the class name *ends with* the interface name minus `I`
  (`…WathiqDbSchemaMigrator`). The migrator "succeeded" while doing nothing for `documents`.
  Fixed with `[ExposeServices(typeof(IWathiqDbSchemaMigrator))]`.
- **`dotnet run --no-build` after `dotnet ef migrations add`** ran a stale `DbMigrator` — the EF
  project was rebuilt by the tool, the migrator's bin copy was not. Drop `--no-build` after adding
  a migration.
- **MSBuild node OOM** (`CombineTargetFrameworkInfoProperties` → `OutOfMemoryException`) on the
  first build after adding four projects; `dotnet build-server shutdown` and rebuild fixed it.
- **Empty migration is correct here**: `Up()` has no body, yet applying it creates the schema and
  the history table — EF's SQL Server history repository emits `CREATE SCHEMA` itself.
- Long bilingual/Python heredocs keep breaking in this Bash tool; generating files from a script
  written with the editor tool is the reliable path.

## Check yourself

1. Why does `DocumentsDbContext` need its own `MigrationsHistoryTable`, and what would happen without it?
2. The `Reminders` module will need `Document` expiry dates. Name the two allowed channels and the one forbidden one.

<details><summary>Answers</summary>

1. Both contexts share one database; without a separate table both would record into
   `dbo.__EFMigrationsHistory`, and each context would consider the other's migrations
   "unknown/pending" (or refuse to apply). The `documents` schema table keeps the ledgers apart.
2. Allowed: an application-service interface returning DTOs (`IDocumentLookup`) and a local event
   (`DocumentExpiryChanged`). Forbidden: mapping `documents.Document` in `RemindersDbContext` — it
   is not referenced, so it cannot compile.

</details>
