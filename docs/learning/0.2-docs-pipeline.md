# 0.2 — Docs pipeline

> **Phase:** 0 · **App:** docs · **Commit:** `step(0.2): add Pandoc docs pipeline with RTL-capable template` · **Date:** 2026-08-27

## What was built

A reproducible Markdown → Word pipeline for all deliverables:
[make-reference.py](../deliverables/_template/make-reference.py) generates the Pandoc reference
template, [build.ps1](../deliverables/_template/build.ps1) renders any `docs/deliverables/<key>.md`
to `out/<Key>.docx`, and [smoke.md](../deliverables/smoke.md) → `out/Smoke.docx` proves headings,
tables, code and an Arabic RTL paragraph all render.

## Topics applied

| Topic | Where in the code | What I already knew it maps to (Angular / ABP / other) |

## The mental shift

A Word deliverable can be treated exactly like a build artifact: source (`.md`) is the thing you
review in diffs, the template is code (`make-reference.py`), and `out/*.docx` is a compiled
output that must be regenerated, never hand-edited. That flips the usual "Word document drifts
from the code" problem — the SRS/DB docs now grow in the same commit as the migration they
describe.

## Gotchas hit

- PowerShell: an inline `# comment` after a backtick line-continuation breaks parsing
  (`Missing expression after unary operator '--'`). Fixed by building an argument array and
  splatting it — also easier to read.
- python-docx has `get_or_add_pPr()` for paragraph styles but no `get_or_add_tblPr()` for table
  styles; had to find/create the `w:tblPr` element by hand.
- Printing Arabic from Python on this console fails with `cp1252`; use `PYTHONIOENCODING=utf-8`
  when inspecting rendered files.
- Pandoc renders only `title/subtitle/author/date` from front matter; `version`/`status` are
  not visible in the docx. Decision: the revision-history table is the version record.
- No `mmdc` (Mermaid CLI) installed, so diagrams for step 0.5 will need an `npx` fallback or
  pre-rendered PNGs in `assets/`.

## Check yourself

1. Why does the `RTL` style set both `w:bidi` (paragraph) and `w:rtl` (run)?
2. Which file do you edit to change heading colours — `reference.docx` or something else?

<details><summary>Answers</summary>

1. `w:bidi` sets paragraph direction/alignment; `w:rtl` marks the run as right-to-left so
   punctuation and mixed Latin tokens are placed correctly inside the Arabic text.
2. `make-reference.py` — `reference.docx` is generated from it and would be overwritten.

</details>
