## The mental shift

`Documents` cannot enumerate users — Identity owns them, and the module boundary forbids the
query — so "every user has a self-holder" cannot be a seed. It became a domain rule instead:
`HolderManager.EnsureSelfHolderAsync` creates it on first contact, and the filtered unique index
makes a second one impossible even if two requests race. The boundary pushed a piece of logic to
the right place; this will be the shape of every cross-module need in Phase 2.

## Gotchas hit

- **Per-context `AbpDbContextOptions.Configure<T>` replaces the global provider.** Step 1.3's
  module registered `UseSqlServer` for `DocumentsDbContext`, so in the test host the context
  ignored the global Sqlite setup and failed with "ConnectionString property has not been
  initialized" the moment the seed opened a connection (1.3's test passed only because it never
  did). Fixed twice: the provider decision moved to the host EF module, and the test module
  now overrides `DocumentsDbContext` with Sqlite explicitly.
- Removing `UseSqlServer` from the Documents EF module also meant dropping its
  `AbpEntityFrameworkCoreSqlServerModule` dependency in favour of `AbpEntityFrameworkCoreModule`.
- One EF test run failed on `DocumentsDbContextTests` right after the rebuild and then passed
  3/3 full runs; not reproduced, logged here rather than papered over.
- Plain domain tests (`DocumentTypeTests`, `HolderTests`) need no ABP host — they finally give
  `Wathiq.Domain.Tests` real tests (it had zero discoverable ones from the template).
