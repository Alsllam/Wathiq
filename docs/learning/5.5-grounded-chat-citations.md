# 5.5 — Grounded chat with citations

> **Phase:** 5 · **App:** backend · **Commit:** `step(5.5): answer guide questions grounded in retrieved chunks with validated citations` · **Date:** 2026-09-03

## What was built

The grounded loop, `POST /api/guides/chat/ask`: retrieve → ask → **validate** → answer or
refuse. The model half is the `IDocumentDataExtractor` pattern replayed for RAG: an
`IGuideAnswerer` seam in Shared, implemented in the Ai module over the **keyed `guides` client**
(so the 3.3 cap/ledger decorator, purpose `GuideChat`, is structurally in every call's path),
with `guides-chat@v1` as a pinned embedded prompt and a pure `GuideAnswerParser` that degrades
every malformed model output to a refusal. The Guides half owns what the model can't be trusted
with: excerpts go to the model as opaque labels `C1..Cn` (never real ids), cited labels are
mapped back against the retrieved set — invented ones dropped with a warning flag, an answer
left with **zero** surviving citations refused whole — and every answer carries the *oldest*
cited source's `LastVerifiedAt`. Chat requires sign-in (no special grant): the per-user cap
needs an identity; reading stays anonymous. Verified live: anonymous ask → login challenge;
authenticated ask on this model-less container → the localized Arabic refusal JSON, because the
retriever now checks the corpus *before* spending a model call.

## The mental shift

Writing the validation layer made the trust boundary crisp: **the model is a text generator
inside an escrow, not a participant that shares our referents.** Everything that must be true —
which excerpts exist, which citations are real, what freshness to display — is computed on our
side of the label boundary, from state the model never touches. Once that's the frame, the
hallucinated-citation policy writes itself: dropping an invented citation isn't error handling,
it's the *definition* of grounding (an answer is grounded exactly insofar as its citations map
into the retrieved set), and an answer with no surviving citations isn't a degraded answer — it
fails the definition, so it's a refusal. The second realization: the refusal message is product
copy, not an error string — it apologizes for nothing, explains *why* refusing protects the
user ("an answer from outside the guides could be wrong"), and gives a next step.

## Gotchas hit

- **The empty-corpus order bug, caught by the live check, not the tests**: the fake-backed tests
  always embed chunks first, so retrieval always had a corpus; only curling the real host (where
  seeded versions have no chunks and no Ollama runs) surfaced that the retriever would dial the
  model before discovering there was nothing to search. Corpus-first is also the right
  fresh-install behavior. Fakes prove logic; the live lap proves *ordering*.
- **Refusal-path determinism needed a sentinel**: with hash-derived fake vectors, "a question
  that matches nothing" isn't constructible reliably - `FakeEmbeddingGenerator.NoMatchSentinel`
  (`:20`) embeds to the zero vector, which cosines to 0 with everything by `VectorMath`'s own
  zero rule. The domain's edge-case decision became test infrastructure.
- **SQL warm-up ≠ SQL up**: after this container restart's docker revival, `docker start` then
  an immediate `sqlcmd` failed - the mssql process needs ~30s before accepting logins. The
  ritual now includes the wait; the host's own retry loop had been masking this.

## Check yourself

1. The model cites `["C1", "C9"]` when only C1..C4 were sent. Walk what the user sees and what
   each layer contributed.
2. Why does the answer carry the OLDEST `LastVerifiedAt` among cited sources rather than the
   newest?

<details><summary>Answers</summary>

1. `GuideAnswerParser` passes both labels through (they're well-formed strings - parsing is not
   validation). `ChatAppService` maps labels against the retrieved set: C1 resolves to its
   chunk, C9 maps to nothing and is dropped, `hallucinatedCitationsDropped` flips true. The
   user sees the answer with ONE citation (guide title, snippet, freshness) plus the warning
   flag the portal can render as "some sources could not be verified". Had C9 been the only
   citation, the whole answer would have been refused.
2. An answer synthesized from several sources is only as fresh as its stalest ingredient - if
   one cited excerpt was verified in January and another yesterday, claiming yesterday would
   launder the January content. Conservative freshness keeps Vision R2 honest.

</details>
