## The mental shift

Quiet hours looked like a formatting detail and turned out to be a **scheduling architecture
question**. With a nightly run, "don't send between 22:00 and 07:00" is unimplementable — 03:00
UTC is inside many quiet windows, so deferral means *never*. The honest fix wasn't cleverness in
the job but changing the operational shape: run the dispatch hourly and let the 2.3 idempotency
(which makes extra runs free) absorb the cost. That's the deeper pattern of this phase: every
"how do I safely do X?" answer keeps coming from the data model, not from more job logic. The
second shift: the module boundary held even for something as mundane as an email address — the
moment `EmailReminderChannel` needed Identity data, the need materialized as a *port in Shared*,
not as a project reference, exactly like file storage did in 1.2.

## Gotchas hit

- `IStringLocalizer.WithCulture` no longer exists (removed from .NET years ago); ABP's
  `CultureHelper.Use("ar")` scope is the current idiom.
- `NullEmailSender` can't be subclassed casually (constructor wants tenant/config/job manager) —
  the recording test double implements `IEmailSender` directly, which is cheaper than satisfying
  a base class built for production.
- The convention bit back, usefully: `EmailReminderChannel : ITransientDependency` auto-exposes
  as `IReminderChannel` (class name ends with the interface name), so every existing job test
  would have double-sent. `RemoveAll<IReminderChannel>()` in the test module, with the class
  itself still resolvable for its own direct test.
- Docker Hub's blob CDN is blocked in this environment, so smtp4dev couldn't be pulled *here* —
  compose still ships it for the dev machine; live verification used `aiosmtpd` (PyPI allowed)
  as the SMTP sink on the same port. The point of `Abp.Mailing.Smtp.Host/Port` config: the sink
  is swappable without touching code.
- A `pkill` embedded in the same command that starts the new host kills the new host's own
  wrapper (its command line contains the binary path). Kill and start must be separate commands
  — third time this class of bug appeared, now written down.

## Check yourself

1. Why does the email channel throw when a user has no email address, instead of quietly
   skipping the reminder?
2. Quiet hours are checked in the job, but the *rule* for them lives on `ReminderRule`. What did
   splitting it that way buy?

<details><summary>Answers</summary>

1. A silent skip leaves the reminder Pending forever with zero trace. The throw becomes a
   `RecordAttempt(succeeded: false)` → a `Failed` status and a `DeliveryLog` row with the error —
   visible to an operator and to the future admin dashboard (FR-REM-005).
2. `IsQuietAt` is a pure predicate on the aggregate: unit-tested with plain `TimeOnly`s
   (midnight wrap included) with no job, clock, or DI involved. The job only supplies "now in
   the user's zone" — the same pure-core/thin-shell split as `ComputeSchedule` in 2.3.

</details>
