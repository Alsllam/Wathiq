> **Phase:** 4 · **App:** frontend · **Commit:** `step(4.5): render documents list and detail as pure derivation` · **Date:** 2026-08-30

## What was built

The first feature lib, `libs/documents` (`type:feature` — the middle boundary tier now exists):
a list where every pixel derives — `httpResource` for the page, a second for the catalogue, a
`computed` id→name join, a `computed` expiry chip — and a detail view whose route id arrives as
a **signal input** (`withComponentInputBinding`), with locale-aware dates and an authenticated
blob download. Routes are guarded (4.4) and lazy-loaded. **Proven live in a real browser**:
login → الوثائق → the seeded passport listed with its Arabic type name and "سارية (3471 يوم)"
chip → detail with the Arabic-formatted expiry and the 13 KB PNG + download. 12 unit tests,
lint, build green.

## The mental shift

A read screen has exactly **one** imperative act — the user's click writing a signal — and
everything else is derivation: URL from page, data from URL, join from two datasets, chip from a
number, date format from locale. Once that shape clicks, "where does the refetch happen?" stops
being a question (nowhere; the URL changed) and the 4.CP answer writes itself: this entire
two-screen feature contains **zero effects** — `computed` covered every need, because nothing
here leaves Angular's world. The second shift is trusting the server with derived *data*
(`daysUntilExpiry` computed under DB6's UTC rules) while keeping derived *presentation*
(severity, label, color) in a pure client function — each side owns what it can test best.

## Check yourself

1. This feature has zero `effect()` calls. Name the two places one might have been tempted and
   what made `computed`/signal-writes sufficient.
2. Why must the attachment download go through `HttpClient` when the list and detail resources
   are also "just HTTP"?

<details><summary>Answers</summary>

1. Refetch-on-page-change (tempting: `effect(() => fetch(page()))`) - unnecessary because the
   resource's URL closure already *reads* `page()`, so the dependency is declared where it is
   used. And the type-name join (tempting: effect writing a map field) - `computed` derives it
   with caching and no ordering hazards. Effects are for leaving Angular's world (4.2's DOM
   sync); nothing here leaves.
2. They all need the bearer token, and all of them get it the same way - through HttpClient
   where the interceptor lives. The difference is the *consumer*: resources feed templates, the
   download feeds the browser's save dialog, which only a blob + object URL can reach. What
   breaks is a plain `<a href>`: it bypasses HttpClient entirely, so no interceptor, no token,
   401.

</details>
