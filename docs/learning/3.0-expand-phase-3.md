## The mental shift

Slicing an AI phase is mostly slicing the *non-AI* parts correctly. Of eight steps, exactly two
touch a live model (3.4, and 3.8's eval numbers); everything else — upload plumbing, usage
ledger, routing walls, OCR staging, validators, review endpoints — is deterministic engineering
that fakes can prove. Writing the expansion made the guardrails' dependency order visible: the
privacy wall (3.3) must exist *before* the model does (3.4), because a wall added after the
fact is a wall you hope nobody crossed already. And the checkpoint question answered itself
during slicing: `30/02/2027` is caught in 3.6's parser layer — the step whose whole topic is
"nothing the model says is trusted".

## Gotchas hit

- `documents.ExtractionResult` lives in the *documents* schema (database.md) while the extraction
  *logic* lives in the `Ai` module — the expansion had to name where the contract sits
  (`IDocumentDataExtractor` in `Shared`, the 2.6 port pattern) so 3.6 doesn't rediscover the
  boundary question mid-implementation.
- The plan's `ai.Prompt` table ("loaded from versioned files, stored for audit") looked
  redundant next to the prompts-as-files guardrail until read carefully: files are the source,
  the table is the audit trail. The expansion keeps prompt files in 3.6 and leaves the audit
  table to land with real usage rather than as empty ceremony.
- This machine may not run a 7B model (disk/network policy); 3.4's step text builds that honesty
  in — record what ran, re-verify on the dev box — instead of letting the step silently become
  "wrote config, hoped".
