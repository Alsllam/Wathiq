> **Phase:** 5 · **App:** frontend + docs · **Commit:** `step(5.7): add the portal guides library with grounded chat, citations and the outdated flag` · **Date:** 2026-09-07

## What was built

UC-03 closed for humans: `libs/guides` (fourth feature lib, the new-lib ritual from memory) with
the **public** guide list and detail — freshness right under the title, the facts card, parsed
body (markdown-lite as *data*, no `innerHTML`), numbered steps, and the anonymous **"outdated?"
button** — plus the **chat screen**: exchanges as a signal array over an imperative POST,
answers rendering **citations as links into the guides** with per-source freshness, the
hallucination-warning chip, honest refusal UI, and a sign-in prompt when signed out (chat rides
the per-user cap; reading never does). The live browser lap proved the whole loop against the
real stack — and caught a real bug: the server localized the refusal in the *browser's*
language, not the app's. Fix: `langInterceptor` in the i18n lib stamps `Accept-Language` from
`LanguageService` on every request — one header, every ABP-localized string now follows the
UI toggle.

## The mental shift

Rendering the chat response forced the realization that **the trust features are the UI**, not
metadata around it. A chat screen that showed only `answer` would look identical on a good day —
and be indistinguishable from a hallucination engine on a bad one. The citations-with-freshness
list, the warning chip, the refusal box with a next step: that's the visible difference between
"a chatbot" and "a grounded assistant", and it all came *free* from 5.5's response contract —
the backend's validation posture dictated the component's states. The second shift came from
the live bug: **localization is split across two runtimes**. Transloco owns the UI strings, ABP
owns error messages and the refusal text, and they follow different signals (app toggle vs
browser header) unless something couples them — the interceptor is that coupling, and only a
real browser could have exposed its absence.

## Gotchas hit

- **`injectApiUrl()` returns a path-builder function** - string-interpolating it produced URLs
  containing the function's source (the test's "requests received" dump literally showed the
  arrow function). The existing libs called `this.apiUrl('/api/…')`; read the neighbor before
  writing the fourth copy.
- **Strict AOT templates vs generated optionals**: jest specs compiled fine, but
  `nx build` (strictTemplates, AOT) rejected `g.version.…` because openapi-typescript marks
  `version` optional. One `@if (g.version; as v)` narrows it for the whole article - unit-green
  is not build-green.
- **A stale vite error overlay blocked every Playwright click** ("vite-error-overlay intercepts
  pointer events") after editing two files seconds apart - the dev server caught the window
  where the wiring existed but the import didn't. The production build (both edits) was already
  green; a serve restart cleared it. Overlays are part of the page as far as a browser is
  concerned.

## Check yourself

1. Why does the guide detail's `httpResource` URL include the language, when the list's doesn't?
2. The live lap found the refusal message in English inside an Arabic UI. Why could no jest
   spec have caught this, and what makes the fix a shared-lib concern rather than a chat fix?

<details><summary>Answers</summary>

1. The list returns BOTH titles per guide and the client picks - one response serves both
   languages. The detail's CONTENT is per-language on the server (latest published version per
   language), so the language is part of the resource's identity; putting `lang.lang()` in the
   URL function makes the switch refetch declaratively.
2. Specs flush hand-written responses - the "server" in a jest test has no localizer, so
   nothing could disagree with the UI language. The mismatch lives between two real runtimes
   (browser Accept-Language vs ABP's localizer). It's a shared-lib concern because EVERY
   ABP-localized string (validation errors, business exceptions) had the same gap - the chat
   was merely where it became visible.

</details>
