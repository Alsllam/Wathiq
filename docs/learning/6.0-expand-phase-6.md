## The mental shift

Expanding a phase in a language the developer doesn't know inverted the usual slicing question.
For Phases 1–5 the question was "what's the smallest useful increment of the *product*?" — here
it became "what's the smallest teachable increment of the *language*, and which product slice
happens to exercise it?" That's why the guides screens come before documents: not product
priority (documents ARE the product) but concept order — `FutureProvider`/`AsyncValue` and
routing are learnable against an endpoint with no auth, while documents would force tokens,
interceptors and error states into the same lesson. The probe-first habit also mattered: one
`curl -I` against the Flutter release URL changed the entire phase's verification story from
"dev-box only, trust me" to "green in this container, hardware for three named things".

## Gotchas hit

- `mobile/README.md` already prescribed the target layout (written in 0.6, before any Flutter
  knowledge existed in the project) — the expansion defers to it rather than re-deriving, same
  as the DB doc drove Phase 5's entities. Plans written early keep paying if you re-read them.
- The proxy denied `accounts.google.com` earlier this session, which nearly justified assuming
  all Google endpoints were blocked — but `storage.googleapis.com` answers 200. Probe the
  actual host you need, not its cousins.
- Firebase/FCM has a free tier but needs a real Google account + project — 6.11 marks setup as
  dev-box work explicitly instead of discovering it mid-step (the "prefer the free/local path"
  rule: FCM *is* the free path for push, there is no self-hosted alternative worth the detour).

## Check yourself

1. Why do the anonymous guides screens (6.4–6.5) come before auth (6.6), when documents are the
   core product?
2. What did the two environment probes change about how the phase's steps are worded?

<details><summary>Answers</summary>

1. Concept sequencing for a first Flutter project: Dio + Riverpod async state + go_router are
   each one new concept against a token-free endpoint; putting documents first would stack
   auth, interceptors and error handling into the same lessons. 5.1's public-read design made
   this ordering possible at all.
2. `which flutter` failing + the release URL answering 200 means the SDK can be installed HERE:
   every step promises in-container `flutter analyze`+`flutter test`, and only three
   hardware-bound things (camera, the OIDC browser dance, FCM delivery) are worded as
   device/dev-box preconditions - the honest split decided by evidence, not assumption.
