# 5.3 — Chunking + bge-m3 embeddings on publish

> **Phase:** 5 · **App:** backend · **Commit:** `step(5.3): chunk and embed guide versions on publish via a background job` · **Date:** 2026-09-03

## What was built

The RAG ingestion pipeline, model-free where it can be: `GuideChunk` rows storing embeddings as
`varbinary(4096)` (1024 × float32, bge-m3) with the producing `EmbeddingModel` recorded; a
**pure heading/size-aware chunker with overlap** (facts line and steps get dedicated chunks —
they answer the most common questions); explicit little-endian `float[]↔bytes` converters; and
`IEmbeddingGenerator` registered behind the Ai module's wall with the **same boot-guard as
extraction** — embeddings run on local bge-m3 only, a cloud provider kills the boot. Publish now
raises a local event whose handler enqueues `GuideEmbedJob` post-commit (the 3.5 lap, fourth
time), and the job rebuilds a version's chunks idempotently. A late-caught gap became a feature:
seeded versions were published *before* the pipeline existed and publish is one-shot, so
`rebuild-embeddings` is a new admin endpoint — also the lever for future model swaps, which is
exactly what the `EmbeddingModel` column anticipates.

## The mental shift

Storing embeddings as bytes forced the question a `VECTOR` type would have hidden: **what
exactly is the contract of this column?** Answering it produced three artifacts a managed type
gives you implicitly — an explicit byte order (`EmbeddingConverter`, little-endian by contract
with a test that fails on unportable layouts), an exact width (`varbinary(4096)` = the model's
dimensionality, proven against the live model by the gated smoke), and a provenance column
(`EmbeddingModel`, because two models' vectors sharing a table would be silent nonsense). The
second shift came from the seed gap: **one-shot events need a manual replay lever.**
Publish-triggers-embed is elegant until content exists that was published before the trigger
did — `rebuild-embeddings` is that lever, and it immediately turned out to be the model-swap
story too. Event-driven pipelines want an explicit "run it again" door, designed in, not bolted
on during an incident.

## Gotchas hit

- **Seeded content would never have been embedded**: publish is one-shot and both seeded
  versions were already published, so the event could never fire again for them — caught while
  writing the migrations-log row, not by any test (the fake-backed tests all publish fresh
  versions). The fix (admin `rebuild-embeddings`) is tested for both the happy path and the
  draft refusal (`VersionNotPublished`).
- **Docker daemon gone mid-step** (container restart between turns): the migrator failed with a
  network error that *looked* like a SQL problem; `docker ps` failing was the real tell. The
  revival ritual (delete stale pidfiles, restart dockerd, `docker start wathiq-sql`) is now
  muscle memory - diagnose the layer below before the layer you're on.
- The token estimator is deliberately not a tokenizer: `max(words, chars/4)` with a comment
  saying it's a packing budget. The test pins the *behavior* (Arabic vs long-unspaced strings),
  not a fictional precision.

## Check yourself

1. Why do the facts line (fees/documents/location) and the steps get their own chunks instead
   of being packed with the body?
2. A future config change points `Ai:Embeddings` at a Groq endpoint. Walk the two independent
   defenses that stop guide text (and later, user questions) from reaching it.

<details><summary>Answers</summary>

1. Retrieval returns whole chunks; the most common questions ("how much? what do I bring?
   where?") are answered by those few dense lines. Packed into a 300-token body chunk they'd be
   diluted - their similarity score would sink under unrelated prose. Dedicated chunks make the
   likeliest answers the sharpest vectors (and steps keep their order, which carries meaning).
2. First, `AiOptions.Validate()` refuses to boot when `Embeddings.Provider != "ollama"` - the
   host never starts. Second, even if validation were deleted, the Guides module cannot reach a
   provider SDK: it only sees `IEmbeddingGenerator`, and the single registration line lives in
   the Ai module - a reviewer sees any provider change as a one-line diff in the one file
   guarded by C1 comments.

</details>
