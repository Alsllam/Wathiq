## The mental shift

Permissions and ownership are two different axes and both are needed. A permission
(`WathiqDocuments.Documents.Create`) answers "may this *kind* of user do this *kind* of action" —
it is a role-shaped, admin-grantable switch. It says nothing about *which rows*. Owner scoping
(`OwnerUserId == CurrentUser.GetId()` on every query, re-checking a client-supplied `HolderId`
actually belongs to the caller) answers "may this user touch this *row*". Coming from admin-style
ABP apps where permission = access, the consumer-app twist is that the permission check is almost
never the interesting one — the ownership check is, and it must throw *not-found*, not
*forbidden*, or the API confirms foreign ids exist. The second shift: a defined permission is
worthless to a self-registered user until something grants it — hence the seeded `IsDefault`
role, which is the missing link between "registration works" (1.1) and "the API answers" (1.6).

## Gotchas hit

- ABP 10 renamed things: `CheckErrors()` for `IdentityResult` now lives in the
  `Microsoft.AspNetCore.Identity` namespace (`AbpIdentityResultExtensions`), and the seeding-side
  provider class in `Volo.Abp.PermissionManagement.Identity` is `RolePermissionManagementProvider`
  — but the `"R"` constant still comes from `Volo.Abp.Authorization.Permissions.RolePermissionValueProvider.ProviderName`.
  Found both by grepping the NuGet package DLLs, not the (outdated) docs in my head.
- The permission constants had nowhere obvious to live: a full ABP module puts them in
  `Application.Contracts`, which our merged four-project layout doesn't have. They landed in
  `Documents.Domain` (the lowest layer both the definition provider and the host seeder already
  reach) with a comment saying exactly that — plus a deliberate host-only `csproj` edge
  `Wathiq.Domain → Wathiq.Documents.Domain`, which is composition, not a module-to-module
  dependency.
- Ordering the list by expiry on an owned type: `d.Validity.ExpiryDate` works fine in LINQ, but
  "nulls last" needs the explicit `OrderBy(d => d.Validity.ExpiryDate == null)` trick — SQL sorts
  `NULL` first by default on SQL Server ascending order.
- The composite index `IX_Document_OwnerUserId_ExpiryDate` deferred from 1.5 stays deferred: EF
  still can't declare an index spanning root + owned-type properties from the fluent API, and the
  two existing single-column indexes serve the timeline query until profiling says otherwise.
- Attachment upload/download endpoints are **not** in this step: they need `IRemoteStreamContent`
  plumbing and arrive with the first consumer (extraction, Phase 3). `Document.RemoveAttachment`
  returning the blob key for post-commit file deletion therefore has no caller yet.

## Check yourself

1. A logged-in user calls `GET /api/documents/document/{id}` with another user's document id and
   the `WathiqDocuments.Documents` permission. What status code comes back, and why that one?
2. Nothing in the host grants permissions to the `admin` role for this module. Why does admin
   still get them after the migrator runs?

<details><summary>Answers</summary>

1. 404. The permission gate passes (right *kind* of action), but `GetOwnedAsync` compares
   `OwnerUserId` with `CurrentUser` and throws `EntityNotFoundException` — deliberately not 403,
   so the response doesn't confirm the id exists.
2. ABP's own `PermissionDataSeedContributor` (PermissionManagement module) grants *every defined
   permission* to the admin role at seed time; our provider only has to define the names.

</details>
