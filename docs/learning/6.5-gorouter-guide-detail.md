# 6.5 — go_router: guide detail

> **Phase:** 6 · **App:** mobile · **Commit:** `step(6.5): route to a deep-linkable guide detail with freshness, steps and the outdated flag` · **Date:** 2026-09-07

## What was built

Navigation became a route table: `MaterialApp.router` + a `GoRouter` whose `/guides/:slug`
route builds `GuideDetailPage` from `state.pathParameters` — deep-linkable, back-button free
(the AppBar infers a pop because the page was *pushed*). The data side pairs the route with a
**`FutureProvider.family`** keyed by slug (and watching the locale, so toggling refetches the
right published version — the portal's two-signal URL, in provider form). The screen ports
5.7's design to Dart: freshness right under the title, the facts card with **`if-case` null
promotion** (`if (version.fees case final v?)` — no `!` anywhere), the body via a pure
`parseGuideBody` using **sealed segment classes** with an exhaustive `switch`, numbered steps,
and the anonymous "outdated?" POST behind a small provider seam (`outdatedFlagSenderProvider`)
that tests override with a recorder. `flutter analyze` 0 issues, 16 tests green.

## The one new concept

**Declarative routing — routes as data.** `GoRouter`'s route list is the Angular route table
verbatim: patterns map to builders, path params are declared in the pattern, and the URL is the
source of truth — `/guides/renew-passport` typed into a deep link lands exactly where a tap
lands. The `push`/`go` distinction carries the mental model: `push` stacks (list stays beneath,
back pops), `go` *replaces the location* (for switching sections). And because routes are data,
the test drives navigation by tapping real UI and asserting real screens — no router mocking,
the route table under test is the shipping one.

## The mental shift

The route table pulled the app's *shape* out of its widgets: before this step, "where can the
user be?" was answered by spelunking `setState` and constructors; now it's one file, and every
screen is addressable by URL — which suddenly matters on mobile for reasons Angular took for
granted (push notification taps, shared links, state restoration all need "a place" to name).
The second shift was noticing how the phase's ideas compose: the family provider is *just* a
provider, the sealed switch is *just* exhaustiveness, if-case is *just* promotion — 6.5 wrote
a whole screen without one genuinely new mechanism beyond the route table, which is what "one
concept per step" is supposed to feel like when the earlier steps landed.

## Gotchas hit

- **`tester.pageBack()` misses localized back buttons**: it hunts by English tooltip/Cupertino
  type, and the ar locale renders a Material `BackButton` with an Arabic tooltip → "0 widgets
  found". `find.byType(BackButton)` is locale-proof - the ar-first suite keeps flushing out
  helpers with en-US assumptions.
- **`DateFormat.yMMMd('ar')` needs its symbols loaded** - in the app the localization
  delegates do it; in tests it works because the full `WathiqApp` (with delegates) is pumped.
  A page-only pump would throw `LocaleDataException`; worth remembering when a test wants to
  skip the shell.
- go_router 16.x resolved fine but `flutter pub get`'s "N packages have newer versions" noise
  hides the actual result line - grep for `Got dependencies` or the package name, not the tail.

## Check yourself

1. Why does the detail's provider watch the locale when the list's provider (6.4) only depends
   on it transitively through Dio?
2. What does `sealed` buy over an abstract base class for `GuideBodySegment`?

<details><summary>Answers</summary>

1. The list endpoint returns BOTH titles and the client picks - language changes the request
   header only (via Dio), and refetching is incidental. The detail endpoint serves per-language
   CONTENT (latest published version for that language), so the language is part of the
   request's identity - watching the locale in the provider makes the toggle refetch by
   construction, same as the portal's two-signal httpResource URL.
2. Exhaustiveness: a `switch` over a sealed type must handle every subclass or it's a compile
   error - add a `TableSegment` tomorrow and every render site lights up. An abstract class
   allows unknown subclasses anywhere, so switches need a default arm and new kinds fail
   silently at runtime instead.

</details>
