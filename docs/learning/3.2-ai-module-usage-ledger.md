## The mental shift

`AiUsage` is the first entity where the *base class* was a real decision rather than a default.
`FullAuditedAggregateRoot` answers "who changed this and can we undo it?" — questions that are
meaningless for a ledger line that is never changed and never deleted. Choosing
`BasicAggregateRoot` + constructor-only state makes immutability structural: there is no setter
to misuse, and `At` is explicit rather than hidden in `CreationTime` because the domain concept
is "when the model call happened", not "when the row was inserted" (they differ under queued
writes). The broader lesson: audit machinery is for *mutable* state; append-only state IS its
own audit.

## Gotchas hit

- The class is `AiUsage` while the table is `Usage` — naming a C# class `Usage` inside namespace
  `Wathiq.Ai.Usage` collides with the namespace segment (CS0542 territory and endless
  qualification); the config's `ToTable("Usage", "ai")` keeps the database matching the DB doc
  while the code keeps a usable name.
- Six wiring points × fourth module = scripted: one Python pass edited slnx, host csproj +
  `DependsOn`, host EF csproj + provider, DbMigrator csproj + `DependsOn`, and the test module's
  three touchpoints, each with an assert-before-replace. The 2.1 "forgetting any one fails
  silently at a different time" risk is now mechanically checked.
- Applied the 2.3 lesson preemptively: rebuilt the migrator *before* running it with
  `--no-build` after `migrations add` — and verified in SQL anyway. Trust, then verify, in that
  order and both.

## Check yourself

1. Why is `AiUsage` a `BasicAggregateRoot` when every other aggregate in the codebase is
   `FullAudited`?
2. What single query justifies `IX_Usage_UserId_At`, and which step will write it?

<details><summary>Answers</summary>

1. It is append-only: never updated, never deleted. Audit columns record change and soft delete
   records removal — neither can ever happen, so the columns would be noise. Immutability is
   enforced structurally (ctor-only, no setters).
2. `COUNT(*) WHERE UserId = @me AND At >= @todayUtc` — the FR-AI-004 daily-cap check, written by
   3.3's `UsageTrackingChatClient` before any call leaves the process.
