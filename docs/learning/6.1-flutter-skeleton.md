`flutter test`: green — both in this container, no device involved.

## The one new concept

**Everything is a widget.** There is no HTML/CSS/TS triad to coordinate: `MaterialApp` (the
app), `Scaffold` (the page), `Center` (layout), `Text` + `TextStyle` (content + typography) are
all values of one type, composed as constructor calls in `app.dart`'s `build()`. What Angular
splits across component class, template, stylesheet and router config collapses into one tree —
and `runApp` (`main.dart:10`) just hands the engine its root. A `StatelessWidget` is a pure
inputs→subtree function: no lifecycle hooks, no change detection strategy to pick; when
something above changes, `build()` simply runs again. The `const` constructor is the first
Dart-specific idea worth internalizing: an immutable widget built once is reusable forever,
and the analyzer nudges toward `const` everywhere it's legal.

## The mental shift

Coming from Angular, the reflex is to ask "where do the template and styles go?" — and the
answer dissolving the question is the real lesson: they don't go anywhere, because *structure,
style and layout are all just more constructor arguments*. Once `Center(child: Text(style:))`
reads as "a div with flexbox centering and a styled span" the fear of the nesting goes away;
the tree IS the template, and Dart's trailing commas + the formatter keep it diff-able the way
Angular templates never quite are. The second shift is how cheap verification is: no emulator,
no browser, no server — `flutter test` boots a headless binding and pumps real widgets in
milliseconds, which reframes widget tests from "expensive e2e-ish things" to "unit tests that
happen to render".

## Gotchas hit

- **The flutter tool refuses to look like it works as root** — prints a superuser warning and a
  paperclip emoji before every command's real output; harmless in a container, but the first
  `flutter --version` looked broken because the version lines came after the scolding. Filter
  the noise, read the content.
- **`git config --global --add safe.directory /opt/flutter`** is part of the install: the SDK
  is a git checkout, and the tool shells out to git to identify its version - as root against
  a non-owned directory, git refuses and flutter mysteriously can't say what version it is.
- `flutter create` in a non-empty directory (our README was already there) works fine and
  merges - but it also drops an `.iml` IDE file and a counter-app test that have no business
  in the repo; deleted both before the first commit rather than after the tenth.

## Check yourself

1. Why can every Phase 6 step verify with `flutter test` in a container that has no display,
   no emulator and no Android SDK?
2. What does `const WathiqApp()` buy, concretely, that `WathiqApp()` doesn't?

<details><summary>Answers</summary>

1. Widget tests run on the Dart VM with a headless test binding: the framework builds the real
   widget tree and lays it out against a fake surface - no GPU, no platform embedder. Only
   things that cross a platform channel (camera, secure storage, FCM) need hardware, which is
   exactly the device/dev-box split the phase expansion drew.
2. A canonical compile-time instance: Flutter can skip rebuilding a const subtree entirely
   (identical instance ⇒ nothing changed), and Dart deduplicates the object. It's the
   memoization the framework gets for free whenever the analyzer's `prefer_const_*` lints are
   satisfiable - performance by immutability, not by change-detection configuration.

</details>
