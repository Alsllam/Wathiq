# 6.4 — Riverpod + Dio: the public guides list

> **Phase:** 6 · **App:** mobile · **Commit:** `step(6.4): fetch the public guides list through Riverpod providers over a locale-aware Dio client` · **Date:** 2026-09-07

## What was built

The app's first network round-trip, deliberately against the **anonymous** guides endpoint
(5.1's public-read design: networking learned with zero auth stacked on top). Three providers:
`localeProvider` (6.3's `setState` preview graduated into a `Notifier` — one writable source of
truth), `dioProvider` (base URL per platform — the Android emulator reaches the host at
`10.0.2.2`, overridable via `--dart-define` — and `Accept-Language` derived by **watching the
locale**, so 5.7's live-caught bug is prevented by construction on day one), and
`guidesListProvider` (a `FutureProvider` decoding through 6.2's models). `GuidesListPage`
renders the exhaustive `AsyncValue.when` — loading spinner, honest error state with retry,
data list Arabic-first with pull-to-refresh — and replaced the guides placeholder in the shell.
`flutter analyze` 0 issues, 13 tests green in-container.

## The one new concept

**Riverpod providers — the signals analogue, outside the tree.** The mapping is nearly 1:1:
`Provider` ≙ `computed`, `Notifier` ≙ a writable signal with methods as the only mutations,
`FutureProvider` ≙ `httpResource`, `ref.watch` inside a provider ≙ reading a signal inside
`computed` (a *dependency edge* — change the locale and the Dio client rebuilds, and everything
watching Dio refetches), `ref.watch` in a `ConsumerWidget.build` ≙ a component reading signals,
and `ProviderScope` overrides ≙ `TestBed.configureTestingModule`. The one genuinely new piece
is `AsyncValue`: where the portal hand-wrote `@if (isLoading) … @else if (error) …` around
httpResource, `when(loading:, error:, data:)` is **exhaustive by type** — omitting a branch is
a compile error, the same promotion to edit-time that null safety (6.2) and typed l10n (6.3)
made.

## The mental shift

Riverpod dissolved the "where does state go?" anxiety by making the answer *topological*: state
belongs to a widget only while exactly one widget cares (`_index` in the shell); the moment a
second, unrelated consumer appears, it moves to a provider — and the locale made that concrete
within one step, because the Dio client (not a widget at all) needed it. The second shift is
recognizing `AsyncValue.when`'s exhaustiveness as part of a *pattern* this phase keeps
repeating: Dart keeps taking conventions the portal enforced by discipline (render all three
resource states, follow the app language on the wire, ar-first fallback) and turning them into
things the compiler checks. The framework is stricter than the reviewer — which is exactly what
a first project in a new language needs.

## Gotchas hit

- **`Override` is not exported by flutter_riverpod 3.x**: a test helper typed
  `List<Override>` failed with `non_type_as_type_argument` even though ProviderScope takes
  exactly that list. Inference at the call site names the type fine - build the ProviderScope
  inline instead of naming the type in a signature. (Riverpod 3 also moved StateProvider to a
  legacy import - `Notifier` is the modern writable, which conveniently pre-answers a third of
  the 6.CP question.)
- **`flutter` commands are cwd-sensitive**: one command ran from the repo root and failed with
  "Expected to find project root" - the backend's MSB1009 lesson in Flutter form; compound
  commands start with `cd /home/user/Wathiq/mobile`.
- Wrote a genuinely bad placeholder edit mid-fix (casting an overrides list `as dynamic`) and
  threw it away for a clean rewrite - noting it here because the temptation to "make the
  analyzer shut up" with a cast is exactly what `strict-casts` exists to make painful.

## Check yourself

1. Trace what happens end-to-end when the user taps the language toggle while looking at the
   guides list.
2. Why is overriding `guidesListProvider` a better test seam than mocking Dio?

<details><summary>Answers</summary>

1. `toggle()` sets the Notifier's state. Three watchers react: MaterialApp rebuilds with the
   new locale (text + RTL flip, 6.3); dioProvider is invalidated (it watches the locale) and
   will rebuild with the new Accept-Language on next read; guidesListProvider is invalidated
   TRANSITIVELY (it watches dioProvider), so the list re-fetches - with the new header - and
   the page walks through loading→data again. One state change, the whole chain re-derives:
   the signals graph, verbatim.
2. The override swaps the value at the exact granularity the UI consumes - the page's contract
   is "a Future of guides", not "Dio returns this JSON". Mocking Dio would re-test 6.2's
   decoding on every UI test and couple screens to wire details; the decode path already has
   its own tests against captured payloads. Override where the seam is, test each layer once.

</details>
