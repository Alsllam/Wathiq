## The mental shift

The audit itself was the lesson. Phase 1's 1.8 wrote the missing tests; this time nearly nothing
was missing — because every step of Phase 2 shipped its tests *with* its behavior, the phase-end
"test step" collapsed into verification plus one genuinely new scenario. And that scenario was
found not by staring at code but by walking the requirement lifecycle: FR-REM-002 and FR-REM-004
were each tested *alone*, but their composition — a reminder that has already been Sent meeting
a renewal — is where the unique-index/reuse design carries the most weight and had no direct
pin. Phase-end quality work, done right, is asking "which *interactions* between proven parts
are still unproven?", not "which files lack tests?".

## Gotchas hit

- The architecture doc's reminder-run sequence (written in 0.5, before any Reminders code)
  confidently shows `Documents.IDocumentLookup` — an interface that never came to exist, because
  2.4's event push made run-time lookup unnecessary. Caught only because 2.4's learning doc left
  a note to check it at phase close. Design docs written ahead of code *will* drift; the system
  needs scheduled reconciliation points, and this was one.
- The lifecycle test's dates need care: expiry `today+1` makes exactly one offset (1-day) due
  today; the renewal to `today+30` makes the 30-day offset due today *again* — picking dates so
  each dispatch round has exactly one expected send keeps every assertion unambiguous.
- Nothing else broke or surprised — 62 tests, first run green. Recorded because "no gotchas in
  the closing step" is itself the measure of how much the phase's earlier gotchas taught.

<details><summary>Answers</summary>

1. Phase 2's steps each shipped their tests with the behavior (job idempotency in 2.5, event
   resync in 2.4, quiet hours and email in 2.6, rule resync in 2.7), so the phase end was an
   audit; the only unpinned thing was an interaction between proven parts — Sent-row re-arm
   across a renewal.

   what makes delivery history per document×offset continuous (FR-REM-005) and the dispatch
   idempotent across renewals (FR-REM-002); four rows could exist in many wrong ways, but the
   same id can only mean reuse.
