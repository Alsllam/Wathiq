## The mental shift

**A test through the real composition tests the contracts between your own layers** — and those
are exactly the ones unit tests silently agree to ignore. 3.3's decorator tests passed
`promptVersion: "v1"` (fits in 16); 3.6's extractor tests faked the decorator away; both green,
and their composition was broken. The 3.8 test's only novelty was wiring the *real* pieces
together — and the bug fell out in the first run. Second shift: an eval set is a *product
artifact with its own invariants* — it needs tests (well-formedness, bilingual balance,
parser-compatible ground truth) exactly like code, because a corrupt label silently corrupts
every future prompt comparison.

## Gotchas hit

- The composition bug itself: `ai.Usage.PromptVersion` nvarchar(16) vs the 19-char
  `extract-document@v1`. The 3.6 widening fixed `ExtractionResult` and I *noted* the doc's 16
  was wrong — but never grepped for other 16s. A found bug's twin usually lives one grep away:
  `grep -rn "MaxPromptVersionLength"` would have caught it two steps earlier.
- `grep -c "0 Error"` on a `tail -1` that was the elapsed-time line — my build-check one-liner
  reported failure for a clean build. Pipelines that *check* checks need checking; MSBuild's own
  `Error(s)` summary line is the thing to read.
- Eval ground truth is a design decision, not transcription: for OCR noise `2033-O7-29` the
  first draft expected null ("parser drops it"), but the document's true expiry is 2033-07-29
  and a model that reads O as 0 is right, not guessing — the label follows the *document*, and
  the eval is allowed to be hard.

## Check yourself

1. Both 3.3's and 3.6's test suites were green — why could only a test like 3.8's catch the
   nvarchar(16) bug, and what's the general rule for where such bugs hide?
2. Why does the eval scorer treat an expected-null field as a graded field instead of skipping
   it?

<details><summary>Answers</summary>

1. The bug lived in the *contract between* layers: the extractor's real prompt-version constant
   vs the ledger's column width. Each unit test substituted the other side (a short "v1", a
   faked decorator), so each side was self-consistent and the disagreement invisible. Rule:
   integration bugs hide wherever two independently-tested components exchange a value neither
   test suite generates realistically — test the seams with real values, fake only the edge you
   don't own (the network).
2. Because "knows when to say nothing" is half the job: FR-AI-003's whole posture is that an
   invented value is worse than an empty field. Skipping nulls would let a hallucinating
   pipeline score identically to a careful one on the hardest cases (the decoy, the Hijri date,
   the broken OCR).

</details>
