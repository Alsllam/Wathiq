This document describes the **actual** API surface: every endpoint listed here was taken from
`GET /swagger/v1/swagger.json` of the running host and exercised with real requests. Planned
endpoints are explicitly marked *Planned*.

# 1. Overview

| Item | Value |
| --- | --- |
| Base URL (dev) | `https://localhost:44352` |
| Style | REST + JSON, generated by ABP auto API controllers from application services |
| Spec | OpenAPI 3.0.4 at `/swagger/v1/swagger.json`, Swagger UI at `/swagger` |
| API version | Single doc `v1` (no URL versioning yet) |
| Total paths | 52 (14 Documents + 3 Reminders module, 35 ABP infrastructure: account, identity admin, permissions, settings) |

The API is **self-describing** twice over: OpenAPI for any client, plus ABP's own
`GET /api/abp/api-definition` (used by ABP client proxy generators) and
`GET /api/abp/application-configuration` (current user, granted permissions, localization texts,
settings — the Angular portal bootstraps from this single call).

# 2. Authentication

OpenIddict runs **inside the host** (no separate identity server). Issuer = base URL.

## 2.1 Clients

| ClientId | Type | Grants | Intended use |
| --- | --- | --- | --- |
| `Wathiq_App` | public | authorization code (PKCE), password, refresh token | Angular portal, Flutter app, scripts |
| `Wathiq_Swagger` | public | authorization code (PKCE) | Swagger UI "Authorize" button |

Scope to request: `Wathiq` (audience `Wathiq`); add `offline_access` for a refresh token.

## 2.2 Getting a token (password grant, dev/testing)

```bash
curl -X POST https://localhost:44352/connect/token \
  -d "grant_type=password&client_id=Wathiq_App&scope=Wathiq" \
  -d "username=salem&password=***"
# → { "access_token": "...", "token_type": "Bearer", "expires_in": 3600 }

curl https://localhost:44352/api/documents/documents \
  -H "Authorization: Bearer <access_token>"
```

The production clients use authorization code + PKCE; the password grant stays for local tools
and integration tests. Self-registration is `POST /api/account/register`
(`userName`, `emailAddress`, `password`, `appName: "Wathiq_App"`).

## 2.3 Permissions

Every Documents action checks an ABP permission (defined in
`DocumentsPermissionDefinitionProvider`, granted per role in `AbpPermissionGrants`):

| Permission | Granted to `user` (default role) | Granted to `admin` |
| --- | --- | --- |
| `WathiqDocuments.DocumentTypes` | yes | yes |
| `WathiqDocuments.Holders` (+ `.Create/.Update/.Delete`) | yes | yes |
| `WathiqDocuments.Documents` (+ `.Create/.Update/.Delete`) | yes | yes |
| `WathiqReminders.Rule` (+ `.Update`) | yes | yes |
| `WathiqReminders.Reminders` | yes | yes |

The `user` role is seeded with `IsDefault = true`, so **every self-registered account gets these
permissions automatically** — no admin action needed. Data access is additionally
**owner-scoped**: a permission lets you act on *your own* rows only (see §3.4).

# 3. Conventions

## 3.1 Serialization

- JSON, `camelCase` property names.
- Calendar dates (`issueDate`, `expiryDate`, `birthDate`) are plain dates: `"2030-09-01"`
  (`DateOnly` server-side — no time, no time zone, per DB6). Instants (`creationTime`) are
  ISO-8601 with offset.
- Enums serialize as **integers**:
  - `DocumentStatus`: 0 Active · 1 Expired · 2 Renewed · 3 Archived
  - `HolderRelation`: 0 Self · 1 Spouse · 2 Child · 3 Parent · 4 Other

## 3.2 Paging and list envelopes

List endpoints take `SkipCount` (default 0) and `MaxResultCount` (default 10, max 1000) as query
parameters and return `{ "totalCount": n, "items": [...] }`. Small global lists (document types,
holders) return `{ "items": [...] }` without paging. Document lists are sorted **soonest expiry
first**, documents without an expiry last, then newest first.

## 3.3 Localization

Send `Accept-Language: ar` (or `en`) — error messages and localized texts come back in that
language. Bilingual data (document type names) always ships both `nameAr` and `nameEn` in one
response; the client picks at render time.

## 3.4 Ownership

All holder and document rows are filtered by the authenticated user. Requesting another user's
row by id returns **404**, never 403 — the API must not confirm that a guessed id exists.

## 3.5 Unauthenticated requests

API clients (with `Accept: application/json`) get **401**; browser-style requests are redirected
(302) to the hosted login page.

# 4. Documents module endpoints

Route root is `/api/documents/*` (module name), resources are plural
(`documents`, `document-types`, `holders`).

## 4.1 Document types (catalogue, FR-DOC-001)

| Method & path | Permission | Description |
| --- | --- | --- |
| `GET /api/documents/document-types` | `WathiqDocuments.DocumentTypes` | Active catalogue entries, sorted by `sortOrder`. Read-only (admin curation is *Planned*, Phase 7) |

`DocumentTypeDto`: `id`, `code` (e.g. `PASSPORT`), `nameAr`, `nameEn`,
`defaultValidityMonths?`, `sortOrder`.

## 4.2 Holders (FR-DOC-007)

| Method & path | Permission | Description |
| --- | --- | --- |
| `GET /api/documents/holders` | `…Holders` | Caller's holders; creates the *self* holder on first call |
| `POST /api/documents/holders` | `…Holders.Create` | Add a family member (`relation` ≠ Self — the self holder is automatic) |
| `PUT /api/documents/holders/{id}` | `…Holders.Update` | Update `fullName`, `birthDate` |
| `DELETE /api/documents/holders/{id}` | `…Holders.Delete` | Rejected for the self holder and for holders that still have documents |

`CreateHolderDto`: `fullName` (required, ≤256), `relation`, `birthDate?`.

## 4.3 Documents (FR-DOC-002/005/006)

| Method & path | Permission | Description |
| --- | --- | --- |
| `GET /api/documents/documents` | `…Documents` | Paged list; filters: `HolderId`, `DocumentTypeId`, `Status` |
| `GET /api/documents/documents/{id}` | `…Documents` | One document |
| `POST /api/documents/documents` | `…Documents.Create` | Create; validates holder ownership and active type |
| `PUT /api/documents/documents/{id}` | `…Documents.Update` | Update `number`, `issueDate`, `expiryDate`, `notes` |
| `POST /api/documents/documents/{id}/renew` | `…Documents.Update` | FR-DOC-006: new validity, keeps `previousExpiryDate`, status back to Active |
| `DELETE /api/documents/documents/{id}` | `…Documents.Delete` | Soft delete |

`CreateDocumentDto`: `holderId`, `documentTypeId` (both required), `number?` (≤64),
`issueDate?`, `expiryDate?` (expiry ≥ issue), `notes?` (≤1024).
`RenewDocumentDto`: `issueDate?`, `expiryDate` (required).

`DocumentDto` (response): `id`, `holderId`, `documentTypeId`, `number?`, `issueDate?`,
`expiryDate?`, `status`, `notes?`, `previousExpiryDate?`, `daysUntilExpiry?`
(server-computed; negative = already expired; null = no expiry known), `creationTime`.

## 4.4 Attachments (FR-DOC-004, API part)

| Method & path | Permission | Description |
| --- | --- | --- |
| `POST /api/documents/documents/{id}/upload-attachment` | `…Documents.Update` | Multipart form field `file`. Allow-list: `image/jpeg`, `image/png`, `application/pdf` (else 403 `UnsupportedFileType`); max 20 MB (else 403 `Wathiq.Shared:FileTooLarge`); sha256 computed server-side |
| `GET /api/documents/documents/{id}/attachment-content/{attachmentId}` | `…Documents` | Streams the file back with its stored content type |
| `DELETE /api/documents/documents/{id}/attachment/{attachmentId}` | `…Documents.Update` | Removes the row; the blob is deleted only after the transaction commits |

`AttachmentDto` (response, also embedded as `attachments[]` in `DocumentDto`): `id`, `mimeType`,
`sizeBytes`, `creationTime`. File names are not stored; blob keys never leave the server.
Encryption at rest is *Planned* (Phase 8); OCR text fills server-side in Phase 3.

Live example (recorded): a 35-byte PNG uploaded, downloaded byte-identical, deleted — the blob
file disappeared from the store after the 204.

# 5. Reminders module endpoints

Route root `/api/reminders/*`. The rule is a **singleton resource** — one per user, so its
routes carry no `{id}`; the caller's identity selects the row (created with defaults on first GET).

| Method & path | Permission | Description |
| --- | --- | --- |
| `GET /api/reminders/rule` | `WathiqReminders.Rule` | The caller's reminder settings; materialises the default (`90,30,7,1`, Email, `Asia/Riyadh`) on first call |
| `PUT /api/reminders/rule` | `…Rule.Update` | Update settings; **resyncs existing reminders in the same transaction**, so `upcoming-list` immediately matches |
| `GET /api/reminders/reminders/upcoming-list` | `…Reminders` | Pending reminders, soonest `dueDate` first; paged (`SkipCount`/`MaxResultCount`) |

`ReminderRuleDto` / `UpdateReminderRuleDto`: `offsetsDays` int[] (1–3650, ≤8 entries — the
server normalizes to descending distinct), `channels` (flags: 1 Email · 2 Push; 0 pauses),
`quietFrom`/`quietTo` (`"22:00:00"`, both-or-neither; over-midnight windows allowed),
`timeZoneId` (IANA, validated — unknown zones are rejected with
`Wathiq.Reminders:UnknownTimeZone`).

`ReminderDto` (response): `id`, `documentId`, `offsetDays`, `dueDate`, `expiryDate`
(server-computed: `dueDate + offsetDays`), `status` (0 Pending · 1 Sent · 2 Failed · 3
Cancelled), `sentAt?`.

Reminder rows are system-managed: they are (re)created by document changes and the rule update,
sent by the hourly dispatch job, and never edited directly — hence no POST/PUT/DELETE.

Live example (recorded): `PUT /api/reminders/rule` with `{"offsetsDays":[45,3], …}` against an
account holding one document expiring `2026-09-04` left exactly one Pending row —
`offsetDays: 3, dueDate: 2026-09-01, expiryDate: 2026-09-04` — the already-sent 7-day reminder
stayed `Sent` (history is immutable), the removed offsets were cancelled.

# 6. Error model

Every error is the ABP envelope `{ "error": { code, message, details, data, validationErrors } }`.

| HTTP | When | `error.code` example |
| --- | --- | --- |
| 400 | DTO validation (missing/too long fields) — `validationErrors` lists each field | — |
| 401 | Missing/invalid token (JSON clients) | — |
| 403 | Permission denied, or a business rule rejected the request | `Wathiq.Documents:ExpiryBeforeIssue` |
| 404 | Row doesn't exist **or belongs to another user** | — |

Reminders business codes: `InvalidOffsets`, `QuietHoursIncomplete`, `UnknownTimeZone`,
`NoEmailAddress` — prefixed `Wathiq.Reminders:`.

Business error codes of the Documents module (message localized via `Accept-Language`):
`ExpiryBeforeIssue`, `HolderNotOwned`, `DocumentTypeNotActive`, `SelfHolderIsAutomatic`,
`CannotDeleteSelfHolder`, `HolderHasDocuments` — all prefixed `Wathiq.Documents:`.

Live example (`Accept-Language: ar`, expiry before issue):

```json
{ "error": {
    "code": "Wathiq.Documents:ExpiryBeforeIssue",
    "message": "لا يمكن أن يكون تاريخ الانتهاء قبل تاريخ الإصدار.",
    "data": { "IssueDate": "2030-01-01", "ExpiryDate": "2020-01-01" } } }
```
